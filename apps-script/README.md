# อัปเดตระบบสมาชิก Admin / User

1. เปิด Apps Script โปรเจกต์เดิม
2. แทนที่ Code.gs ทั้งหมดด้วยไฟล์ Code.gs ในโฟลเดอร์ outputs ชุดนี้ แล้วบันทึก
3. ทำให้ใช้งานได้ > จัดการการทำให้ใช้งานได้ > รูปดินสอ > เวอร์ชันใหม่ > ทำให้ใช้งานได้
4. ใช้ ADMIN_KEY เดิมที่ตรงกับ APPS_SCRIPT_ADMIN_KEY ของเว็บไซต์
5. เปิด Google Sheet > แชร์ > การเข้าถึงทั่วไป เป็น “จำกัด” และให้สิทธิ์เฉพาะเจ้าหน้าที่ที่จำเป็น เพราะชีต users จะเก็บข้อมูลบัญชีและแฮชรหัสผ่าน เว็บไซต์อ่านชีตผ่านสิทธิ์เจ้าของ Apps Script ผู้จองไม่ต้องได้รับสิทธิ์ Sheet
6. เปิด /login เพื่อสมัครบัญชี User แล้วทดสอบเข้าสู่ระบบ

ระบบเพิ่มชีต users และคอลัมน์ user_id ใน bookings ให้อัตโนมัติเมื่อใช้งาน ไม่ต้องลบข้อมูลเดิม

## สิทธิ์
- ผู้เยี่ยมชมดูห้องว่างและตารางสาธารณะได้ ต้องเข้าสู่ระบบก่อนจอง
- User สมัครเอง ดูรายการของตน ค้นหาด้วยรหัสการจอง และยกเลิกของตน
- Admin ดูรายการทั้งหมด อนุมัติ ปฏิเสธพร้อมเหตุผล ยกเลิก จัดการห้อง ปรับบทบาท/ปิดบัญชี/ตั้งรหัสผ่านสมาชิกใหม่ และดูประวัติ
- บัญชี Admin หลักใช้ชื่อผู้ใช้และรหัสผ่านจาก Environment Variables เดิม
- รายการเก่าที่ไม่มี user_id ต้องให้แอดมินเลือกบัญชีเจ้าของใน “จัดการระบบ > บัญชีผู้ใช้ > ระบุเจ้าของรายการเดิม”
- ไม่ผูกรายการเก่าตามรหัสนักศึกษาอัตโนมัติ และไม่ใช้ PIN
- รีเซ็ตรหัสผ่านหรือปรับสิทธิ์สมาชิกแล้ว session เดิมหมดผล ต้องเข้าสู่ระบบใหม่

## ผลทดสอบ
Lint, TypeScript, Production Build ผ่าน
ชุดทดสอบ Apps Script จำลอง 6 กรณีผ่าน: สิทธิ์ API, เจ้าของรายการ, เวลาซ้ำและสถานะ, เหตุผลปฏิเสธ, วันเวลา, บัญชีและการผูกรายการเดิม
ยังไม่ยืนยันการสมัคร จอง และยกเลิกครบวงจรบน Google จริง จนกว่าจะอัปเดต Apps Script
การจำกัดคำขอใน Next.js ยังเป็นหน่วยความจำต่อเซิร์ฟเวอร์ ไม่ใช่ตัวจำกัดแบบใช้ร่วมกันทุกเครื่อง
